Three polish sub-features. Every honesty rule the spec tests is a **pure function** in
`@savvy/core` (unit-tested via root vitest); the React/CSS layer just renders those decisions.
Motion is pure-CSS gated by `@media (prefers-reduced-motion: no-preference)` (no JS hook on
this branch), so reduced-motion is respected by construction.

## A — SageCore orb pulse = real runs/hour
- **Pure:** `pulseDurationSeconds(runsLastHour)` in `packages/core/src/showcase-motion.ts`.
  0/hr → slow idle breath; otherwise period = `3600/runsLastHour` floored at a safety min so
  it **never pulses faster than the real cadence** (`pulses/hour ≤ runsLastHour`). Unit-tested.
- **Query:** none new — `command-center/page.tsx` already loads `runWindow` (30d); filter to
  `startedAt ≥ now−1h` for `runsLastHour`.
- **UI:** `SageCore` gains `runsLastHour?: number`; sets `--pulse-rate` inline; a new
  `.anim-orbpulse` class in `globals.css` binds `animation-duration: var(--pulse-rate)` **only**
  inside the reduced-motion media block.

## B — coverage-cell glow + toast on fail/stale→pass
- **Pure:** `coverageWins(prev, next): string[]` — checkKeys that went `fail|stale → pass`
  only. **`skip→pass` never celebrates; already-`pass` never glows; first load (no prev) never
  celebrates.** Unit-tested (covers the spec's "skipped doesn't celebrate / already-green
  doesn't glow").
- **UI:** extract the money proof rows into a client `ProofRows` (`components/money/`) that
  SSRs the initial rows, then polls `/api/coverage` every `POLL_SECONDS`, diffs prev→next with
  `coverageWins`, fires `toast.success` + a transient `.anim-glow` per win. New
  `/api/coverage/route.ts` reuses `getVerificationProof()`. Glow = CSS in the media block
  (reduced-motion safe); toast is informational (always).
- **e2e:** seed a check `fail` → load `/money` → insert newer `pass` run → after a poll the row
  flips to `pass` and a toast appears.

## C — enrichment fill-in on live lead view
- **Pure:** `justCompleted(prev, next): boolean` (a run was in-flight, now isn't).
- **UI:** client `EnrichmentLive({ leadId })` on the lead page watches `useInflight('lead',id)`;
  when a run completes it calls `router.refresh()` so null enrichment fields fill in. No run →
  server just renders the value, no animation (spec fallback).
- **e2e:** lead with null enrichment + a running enrich run shows "No enrichment yet"; complete
  the run + fill the property → after a poll the values appear.
